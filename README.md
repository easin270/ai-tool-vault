# AI Tool Vault

A dependency-free, multi-page static publication. Vanilla HTML, CSS and browser JavaScript are generated by a small Node build script so every page has the same navigation, footer and metadata. There are no backend APIs, paid dependencies or analytics. Approved Adsterra units load automatically on selected content pages.

## Run locally

Use Node.js 20 or later. No dependency installation is necessary.

```sh
node scripts/build.mjs
node --test tests/*.test.mjs
node scripts/serve.mjs
```

Open http://127.0.0.1:4173. Stop the server with Ctrl+C. Rebuild and refresh after editing. Serve over HTTP; opening generated HTML with `file://` will not support root-relative paths and ES modules correctly.

Equivalent npm scripts are `npm run build`, `npm test`, and `npm run dev`. On the development machine the global npm installation failed with a missing internal module; the direct Node commands were used successfully. No system npm repair was attempted.

## Included

- 33 generated routes including a custom 404, shared navigation and footer.
- 12 original guides, each with six topic-specific sections, a practical example, breadcrumbs and related links.
- 10 AI directory entries with search, categories, editorial/A–Z/Z–A sorting and official links.
- Six calculators, currency labels for USD/GBP/CAD/AUD (no conversion), input validation, explanations and reset.
- Six-step side hustle finder with back/restart and three explained matches.
- Rule-based business idea explorer with effort, starting steps and cautions.
- Five copyable and downloadable plain-text templates.
- About, Contact, Privacy, Advertising Disclosure, Terms and Editorial Standards / Earnings Disclaimer pages.

All guide and directory content is static HTML and remains readable without JavaScript. Interactive tools require JavaScript; downloads remain ordinary links. Clipboard failure produces a download/manual-copy fallback message. Forms do not send data to a backend. Each calculator documents its formula in its result. Financial scenarios are illustrative, with no tax calculations or earnings promises.

## Domain and contact configuration

`SITE_URL` is the final HTTPS origin with no path, for example `https://your-real-domain.tld`. Set your actual origin, not the example. It controls canonical tags, Open Graph URLs and the sitemap. An unset origin deliberately creates a preview build: no canonical tags, an empty documented sitemap and `robots.txt` disallowing crawling. Robots directives are not an access-control or confidentiality mechanism.

`CONTACT_EMAIL` must be your real, monitored address. Until set, Contact honestly says no monitored contact channel is configured. Never publish invented contact details. Review the owner identity, privacy notice, terms and hosting practices before public launch.

PowerShell configuration:

```powershell
$env:SITE_URL = 'https://YOUR-ACTUAL-DOMAIN'
$env:CONTACT_EMAIL = 'YOUR-ACTUAL-CONTACT-ADDRESS'
node scripts/build.mjs
```

Set these separately for production in Cloudflare. Leave `SITE_URL` unset for non-indexable preview builds, or configure an appropriate preview policy. After changing a domain, rebuild and verify canonical tags, sitemap URLs and robots.txt before submitting the sitemap to search engines. No invented Organization identity, reviews or ratings are emitted. Breadcrumb structured data is generated only when the origin is configured.

## GitHub and Cloudflare Pages

Nothing has been pushed or deployed. The following steps are for the owner after approval.

1. Create a GitHub repository, review the source and initialize Git if needed. Commit the source (generated `dist/` is ignored). Add the repository as `origin` and push your chosen production branch. Check that no personal data or secrets are in the files.
2. In Cloudflare, create a Pages project and connect that GitHub repository. Select the production branch, typically `main`.
3. Set **Framework preset: None**, **Build command: `node scripts/build.mjs`**, **Build output directory: `dist`**, **Root directory: repository root**. Use a supported Node version of at least 20; no install step is required by this project.
4. Set production `SITE_URL` and `CONTACT_EMAIL`. If you do not yet know the final pages.dev origin, use a non-indexable initial preview, then set the known origin and rebuild before public launch.
5. After approval, deploy. Check home, a nested guide, calculator behavior, a download and an unknown URL. Confirm the unknown URL returns HTTP 404, not a success response.
6. Verify `_headers` are applied, canonical URLs match the chosen domain, and `sitemap.xml` contains all 32 public content routes (404 excluded). Configure a custom domain only if desired and authorized.

Official references checked November 20, 2026: [Cloudflare static HTML guide](https://developers.cloudflare.com/pages/framework-guides/deploy-anything/) and [build configuration](https://developers.cloudflare.com/pages/configuration/build-configuration/). Dashboard labels may change. This project uses a custom build command because it generates reusable layouts.

## Privacy, security and ads

Approved advertising units load automatically on selected content pages. The provider may receive request and device information and use cookies or similar technologies. There is no Accept ads prompt or saved advertising preference. Placement counts and responsive restrictions remain documented in ADVERTISING.md.
